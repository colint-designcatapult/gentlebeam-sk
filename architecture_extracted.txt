1: Purpose 
The purpose of this document is to describe the top-level architecture for the software components 
developed by Empyrean Medical Systems for the Voxel Ray GentleBeam system, known as Project 
Heracles. 
This document presents the software components from multiple points of view, describing the system 
context and logical software items, including SOUP components, developer configurations, and other 
viewpoints. 
 
 
 
2: Scope 
This document describes the software components for the Voxel Ray GentleBeam system, known as 
Project Heracles, at a high‐level. The document does not address requirements, electro‐mechanical 
designs, detailed software designs, or verification protocols (all of which other project documents cover). 
*The term Software relates to both software and firmware subsystems.

5: Context View 
The Heracles (AKA GentleBeam) software consists of the following: Heracles Internal SW, Heracles 
External SW, and Record and Verify SW. 
These software components provide the operator with interfaces that enable the delivery of superficial 
radiation therapy to patients using the Heracles system. 
The interfaces will include managing patients’ demographics, acquiring images, and control and 
monitoring the delivery of the radiation treatment.

8: Manufacturing /Service View 
Empyrean Medical Systems Manufacturing and Service personnel are provided with tools and data that 
can be used to access a device’s maintenance interface. 
1. Maintenance Operations 
 
a. Device Provisioning 
i. Assigning unique identifiers such as serial numbers, software versions, and 
firmware details during manufacturing or deployment. 
ii. Configuring default settings for integration into the clinical environment. 
b. Diagnostics and Debugging 
i. Logging errors and warnings into the system for troubleshooting. 
ii. Providing debugging tools to engineers, such as diagnostic UI modules. 
 
c. Event detection and logging  
i. Logging events using Sysmon service 
 
 
2. Updates and Patches 
a. The device will receive at least 1 yearly update during preventative maintenance. The device will 
receive updates and security patches at any point in time once one will be necessary.  
b. All updates will be performed by a trained service engineer using physical USB drive to deliver the 
updates to the device. The updates will be executed by an administrative user. 
c. Patching the application components to address new features, security vulnerabilities, or 
performance improvements. 
 
d. Updating dependent SOUP libraries when necessary.
